# פעולות, מחרוזות ושגיאות

## פעולות

**פעולה** (מתודה, פונקציה) - קטע קוד **עם שם**, שמקבל **פרמטרים** ואולי **מחזיר ערך**. במקום לכתוב את אותו קוד שוב ושוב - **קוראים** לפעולה.

### המבנה

```csharp
public static int Add(int a, int b)   // access, static, return type, name, parameters
{
    return a + b;
}
```

```csharp
int s = Add(3, 4);                   // call: s == 7
```

| חלק | משמעות |
|---|---|
| ‏`public` / `private` | **מי** יכול לקרוא לפעולה |
| ‏`static` | שייכת **למחלקה**, לא לעצם (ראו [מחלקות](03-classes-and-algorithms.md#מחלקות-ועצמים)) |
| **טיפוס מוחזר** | ‏`int`, `bool`, `int[]`... או **`void`** - לא מחזירה כלום |
| **שם** | פועל משמעותי: `IsPrime`, `CountDigits` |
| **פרמטרים** | טיפוס ושם לכל אחד |

### ‏return

- פעולה שמחזירה ערך **חייבת** `return` - **בכל מסלול אפשרי** (כולל כל ענפי ה-`if`). אחרת - שגיאת קומפילציה.
- ‏`return` **מסיים** את הפעולה מיד.
- פעולת `void` - **בלי** ערך מוחזר (אפשר `return;` ריק כדי לצאת מוקדם).

```csharp
public static bool IsPrime(int n)
{
    if (n < 2)
        return false;
    for (int i = 2; i * i <= n; i++)
        if (n % i == 0)
            return false;      // found a divisor - stop
    return true;               // no divisor found
}
```

### פרמטרים

- בקריאה: **מספר**, **טיפוסים** ו**סדר** הפרמטרים חייבים להתאים להגדרה. **השמות** - לא.
- **העברה לפי ערך** (by value): הפעולה מקבלת **עותק**. שינוי פרמטר `int` בתוך הפעולה **לא משפיע** על המשתנה של הקורא.
- **אבל**: מערך ועצם - מה שמועתק הוא **ההפניה**. לכן שינוי **תוכן** המערך בתוך הפעולה **כן** משפיע על הקורא! (ראו [הפניות](03-classes-and-algorithms.md#הפניות-ועצמים-מורכבים).)

```csharp
static void Twice(int x)    { x *= 2; }      // caller's variable is unchanged
static void Clear(int[] a)  { a[0] = 0; }    // caller's array IS changed
```

### תיעוד פעולה

בשורה או שתיים מעל הפעולה:

- **מה היא מקבלת** (קלט) ו**מה מחזירה** (פלט).
- **הנחות** - למשל "המערך לא ריק", "n חיובי".
- **לא** לתאר את המימוש שורה אחרי שורה. כדאי להסביר רק שורות **מתוחכמות**.

### טיפים

- **השתמשו בפעולות שכבר כתבתם** - גם בשאלות הבאות בבחינה ("היעזרו בפעולה מסעיף א'").
- **ערך שצריך כמה פעמים** - שמרו במשתנה, ואל תקראו לפעולה שוב ושוב.
- בדקו שבכל קריאה **כל הפרמטרים** מועברים.

### שאלות לחזרה

- מה ההבדל בין פעולה `void` לפעולה שמחזירה ערך?
- למה הפעולה הבאה לא מתקמפלת? `static int Sign(int x) { if (x > 0) return 1; if (x < 0) return -1; }`
- מה ההבדל בין העברת `int` להעברת מערך לפעולה?
- כתוב פעולה שמקבלת מספר ומחזירה את מספר הספרות שלו.


## מחרוזות ותווים

### מחרוזת

**מחרוזת** (`string`) - רצף של **תווים**. ניגשים לתווים **כמו למערך**: `s[0]` הוא התו הראשון, `s.Length` הוא האורך.

**אבל**: מחרוזת היא **בלתי ניתנת לשינוי** (immutable) - **אי אפשר** לכתוב `s[0] = 'A'`. כל "שינוי" **בונה מחרוזת חדשה**, וצריך להציב אותה בחזרה:

```csharp
s = s.ToUpper();                                  // s.ToUpper() alone does nothing to s
s = s.Substring(0, 3) + "X" + s.Substring(4);     // "replace" the character at index 3
```

**שרשור** - באמצעות `+`: `"a" + "b"` הוא `"ab"`.

### פעולות שימושיות

```csharp
int len = s.Length;              // length
char c = s[i];                   // i-th character (read only)
string t = s.Substring(i);       // from index i to the end
string u = s.Substring(i, k);    // k characters starting at index i
int p = s.IndexOf('x');          // first position of 'x', or -1 if missing
int q = s.IndexOf("ab", i);      // first position of "ab" starting from index i
int r = s.LastIndexOf('x');      // last position
bool b = s.Equals(t);            // same content? (also: s == t)
int cmp = s.CompareTo(t);        // < 0, 0, > 0 - alphabetical order
string v = s.Replace("a", "b");  // replace all occurrences
string w = s.Trim();             // remove spaces at both ends
string x = s.ToUpper();          // also ToLower()
string y = s.Insert(i, "abc");   // insert at index i
string z = s.Remove(i, k);       // remove k characters from index i
char[] arr = s.ToCharArray();    // to an array of characters
```

**שימו לב**: `Substring(i, k)` - הפרמטר השני הוא **אורך**, לא אינדקס סיום!

### תווים

**תו** (`char`) - בגרש בודד: `'a'`. כל תו הוא בעצם **מספר** (קוד). לכן אפשר לחשב:

```csharp
int digit = c - '0';             // '7' -> 7
int index = c - 'a';             // 'a' -> 0, 'b' -> 1 ...
char next = (char)(c + 1);       // 'a' -> 'b'
```

| פעולה | מחזירה `true` אם התו... |
|---|---|
| ‏`Char.IsLetter(c)` | אות |
| ‏`Char.IsDigit(c)` | ספרה |
| ‏`Char.IsLetterOrDigit(c)` | אות או ספרה |
| ‏`Char.IsWhiteSpace(c)` | רווח |
| ‏`Char.IsUpper(c)` / `Char.IsLower(c)` | אות גדולה / קטנה |

ו-`Char.ToUpper(c)` / `Char.ToLower(c)` - מחזירות את התו המומר.

### תווים מיוחדים

בתוך מחרוזת, `\` מתחיל **תו מיוחד**:

| כתיבה | משמעות |
|---|---|
| ‏`\n` | שורה חדשה |
| ‏`\t` | טאב |
| ‏`\"` | מירכאות |
| ‏`\'` | גרש |
| ‏`\\` | לוכסן הפוך |

**`@` לפני מחרוזת** - מבטל את התווים המיוחדים: `@"C:\users\docs"`.

### דוגמה: האם מחרוזת היא פלינדרום

```csharp
public static bool IsPalindrome(string s)
{
    for (int i = 0; i < s.Length / 2; i++)       // only up to the middle
        if (s[i] != s[s.Length - 1 - i])
            return false;
    return true;
}
```

### שאלות לחזרה

- למה `s.ToUpper();` לבד לא משנה את `s`?
- מה מחזיר `"computer".Substring(3, 2)`?
- איך הופכים תו ספרה (`'5'`) למספר?
- כתוב פעולה שסופרת כמה תנועות (`a, e, i, o, u`) יש במחרוזת.


## שגיאות ואיתור באגים

### שלושה סוגי שגיאות

| סוג | מתי מתגלה | מה קורה | דוגמה |
|---|---|---|---|
| **תחביר** (קומפילציה) | **לפני** ההרצה - הקומפיילר מסרב | התכנית **לא רצה בכלל** | חסר `;`, סוגר לא נסגר, שם משתנה באיות שגוי, טיפוס לא מתאים |
| **זמן ריצה** (חריגה) | **בזמן** ההרצה | התכנית **קורסת** באמצע | חריגה מגבולות מערך, חילוק באפס, `null.Length` |
| **לוגית** (סמנטית) | רק כש**בודקים את הפלט** | התכנית **רצה עד הסוף** - אבל עושה **משהו אחר** ממה שרצינו | `<=` במקום `<`, מונה שלא אופס, חילוק שלמים במקום ממשי |

**השגיאה הלוגית היא הקשה ביותר**: המחשב לא מתלונן - הוא עושה **בדיוק מה שכתבנו**. הבעיה היא שזה **לא מה שהתכוונו**.

### באג

**באג** = **פער** בין מה **שחשבנו** שיקרה לבין מה **שקרה**. כלומר - יש חלק בקוד **שלא הבנו** איך הוא פועל, או **שלא השתמשנו בו נכון**.

### איך מאתרים באג

1. **מה סוג השגיאה?** (תחביר? ריצה? לוגית?)
2. **קוראים את הודעת השגיאה** - היא בדרך כלל אומרת **מה** ו**איפה**.
3. **הולכים לשורה** וקוראים אותה בעיון.
4. **מצמצמים** - מנסים לגלות **באיזה חלק** הבעיה. כשהקוד **מחולק לפעולות**, קל יותר: בודקים כל פעולה לבד.
5. **מדפיסים ערכי ביניים** - כדי לוודא שכל חלק עושה מה שחושבים.
6. **מריצים בראש** - בטבלת מעקב, שורה אחרי שורה, **בלי לדלג**.
7. **ניסוי וטעייה** - משנים דבר **אחד** בכל פעם.

**עזרים**: התיעוד של השפה, תרגילים קודמים, חיפוש באינטרנט, חברים.

### בדיקת תכנית

- מריצים על **מגוון קלטים**: רגילים, **מקרי קצה** (מערך ריק, איבר אחד, מספר שלילי, אפס, הערך הראשון או האחרון), וקלטים לא תקינים.
- **בבחינה**: אם השאלה נותנת **דוגמה** - בדקו עליה את הפתרון בטבלת מעקב. הדוגמה בדרך כלל כוללת את **מקרי הקצה** החשובים.

### שאלות לחזרה

- מה ההבדל בין שגיאת זמן ריצה לשגיאה לוגית? תן דוגמה לכל אחת.
- למה קל יותר לאתר באג בקוד שמחולק לפעולות?
- אילו מקרי קצה כדאי לבדוק בפעולה שמוצאת את המקסימום במערך?
