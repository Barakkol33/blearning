# מדריך קלוד (Claude) למי שלא מתכנת (מתקדם)

החלק הזה טכני יותר ולא חובה. הוא מיועד למי שעבד עם [מדריך הבסיס](../01-basics/basics.md) ורוצה להבין מה קורה מאחורי הקלעים. לא צריך לזכור את הפקודות: קלוד מכיר אותן ויכול להפעיל אותן בשבילכם.

> **הבהרה:** זה מדריך אישי ולא רשמי. הוא לא קשור ל-Anthropic או לאף אחד מהכלים והשירותים שמוזכרים בו, ואין לי קשר עסקי אליהם. אלה המלצות מהניסיון שלי, והמידע עלול להתיישן. השתמשו בהן על אחריותכם. אני לא לוקח אחריות על התוצאות, כולל אובדן או דליפה של קבצים ומידע.

## תהליכים

המחשב מריץ הרבה תוכנות בו-זמנית, וכל אחת מהן נקראת **תהליך** (process). הדפדפן, Microsoft Word וקלוד הם תהליכים נפרדים.

לכל תהליך יש:
- **קובץ הרצה:** קובץ התוכנה עצמו (למשל `chrome.exe`).
- **תיקיית עבודה** (working directory): התיקייה שהתהליך פועל בה כברירת מחדל, כמו התיקייה שפתוחה לכם בסייר הקבצים.
- **שורת פקודה:** הפקודה שהפעילה אותו, כולל אפשרויות (למשל `code my-project/`).
- **משתני סביבה** (environment variables): הגדרות מערכת שהתהליך יכול לקרוא, כמו שם המשתמש או המקום שבו נמצאות תוכנות מותקנות.

### דוגמה

כשפותחים את VS Code, המחשב מפעיל תהליך:
- **קובץ הרצה:** `C:\Program Files\Microsoft VS Code\Code.exe` (ב-Windows)
- **תיקיית עבודה:** התיקייה שפתחתם ב-VS Code
- **שורת פקודה:** `code my-project/` (אם פתחתם אותו מהטרמינל)
- **משתני סביבה:** למשל `PATH` (איפה המחשב מחפש תוכנות)

אפשר לראות את כל התהליכים שרצים ב:
- ‏**Windows:** מנהל המשימות (Task Manager, `Ctrl+Shift+Esc`)
- **Mac:** Activity Monitor
- ‏**Linux:** System Monitor, או `htop` בטרמינל

## שורת הפקודה (טרמינל)

### מה זה?

שורת הפקודה (נקראת גם טרמינל או shell) היא דרך טקסטואלית לדבר עם המחשב. במקום ללחוץ על סמלים, מקלידים פקודות. הטרמינל של VS Code (`` Ctrl+` ``) הוא אותו דבר.

יש תוכנות טרמינל שונות, לפי מערכת ההפעלה:

- ‏**Bash** (Mac ו-Linux): ברירת המחדל ב-Mac (או zsh הדומה לו) וברוב מערכות Linux. זמין גם ב-Windows דרך WSL (Windows Subsystem for Linux).
- ‏**CMD** (Windows): שורת הפקודה הקלאסית של Windows. בסיסית ומוגבלת, אבל מותקנת מראש.
- ‏**PowerShell** (Windows): טרמינל חזק יותר של Windows. מותקן מראש בגרסאות החדשות, ושמות הפקודות בו שונים מאלה של Bash.

> רוב המדריכים והכלים ברשת מניחים שמשתמשים ב-**Bash**. אם אתם ב-Windows, שקלו להתקין [WSL](https://learn.microsoft.com/en-us/windows/wsl/install) כדי לקבל טרמינל Bash, או השתמשו ב-PowerShell, שתומך בהרבה פקודות דומות.

### דוגמה

כך נראה שימוש בשורת הפקודה:

```bash
$ pwd
/home/user/my-project

$ ls
index.html  style.css  script.js  images/

$ cd images
$ ls
logo.png  photo.jpg

$ cd ..
$ python script.py
Hello, world!
```

הסימן `$` נקרא **prompt**: הוא מראה שהטרמינל מוכן לקלט. לא מקלידים אותו בעצמכם.

### פקודות שימושיות

| פעולה | Bash (Mac/Linux) | CMD (Windows) | PowerShell (Windows) |
|---|---|---|---|
| איפה אני? | `pwd` | `cd` | `pwd` |
| הצגת קבצים | `ls` | `dir` | `ls` |
| כניסה לתיקייה | `cd folder` | `cd folder` | `cd folder` |
| עלייה תיקייה אחת למעלה | `cd ..` | `cd ..` | `cd ..` |
| הצגת תוכן קובץ | `cat file.txt` | `type file.txt` | `cat file.txt` |
| העתקת קובץ | `cp file.txt copy.txt` | `copy file.txt copy.txt` | `cp file.txt copy.txt` |
| שינוי שם או העברה | `mv old.txt new.txt` | `ren old.txt new.txt` | `mv old.txt new.txt` |
| מחיקת קובץ | `rm file.txt` | `del file.txt` | `rm file.txt` |
| יצירת תיקייה | `mkdir new-folder` | `mkdir new-folder` | `mkdir new-folder` |
| הרצת Python | `python script.py` | `python script.py` | `python script.py` |
| פתיחה ב-VS Code | `code file.txt` | `code file.txt` | `code file.txt` |

> **זהירות:** `rm` ו-`del` מוחקים לצמיתות, בלי סל מחזור!

### טיפים

- לחצו **Tab** להשלמה אוטומטית של שמות קבצים ותיקיות (עובד בשלושתם)
- לחצו **חץ למעלה** כדי לחזור לפקודות קודמות
- לחצו `Ctrl+C` כדי לעצור פקודה שרצה

## Python

### מה זה?

‏Python היא שפת תכנות ידידותית למתחילים, שמשמשת לסקריפטים, עיבוד נתונים, אוטומציה ועוד. במדריך הבסיס למדתם שקלוד משתמש בה מאחורי הקלעים. כאן תלמדו איך זה עובד.

### איך מריצים

**מהטרמינל:**

```bash
python my_script.py
```

**מ-VS Code:**

1. פתחו קובץ `.py`
2. לחצו על כפתור ההפעלה (למעלה מימין) או `Ctrl+F5`
3. הפלט יופיע בפאנל הטרמינל

### מודולים ו-pip

ל-Python יש אוסף עצום של **מודולים** (נקראים גם חבילות או ספריות): קוד מוכן שאנשים אחרים כתבו כדי שאתם לא תצטרכו. למשל, `pandas` לעבודה עם גיליונות נתונים, `requests` להורדת דפי אינטרנט, או `markdown_pdf` להמרת Markdown ל-PDF.

כדי להתקין מודולים משתמשים ב-**pip** (מנהל החבילות של Python) בטרמינל:

```bash
pip install pandas              # install a module
pip install pandas requests     # install multiple at once
pip install pandas==2.1.0       # install a specific version
pip list                        # see what's installed
pip uninstall pandas            # remove a module
```

אחר כך משתמשים בו בקוד Python:

```python
import pandas
```

> אם סקריפט Python נכשל עם `ModuleNotFoundError: No module named 'xxx'`, צריך קודם להריץ `pip install xxx`.

### טיפים

- ודאו ש-Python מותקן: הריצו `python --version` בטרמינל
- התקינו את הרחבת Python ב-VS Code לתמיכה טובה יותר

> **לקריאה נוספת:** [Python for Beginners (המדריך הרשמי)](https://docs.python.org/3/tutorial/)

## Git

### מה זה?

‏Git היא **מערכת ניהול גרסאות**: היא עוקבת אחרי כל שינוי שעשיתם בקבצים לאורך זמן. חשבו עליה כעל היסטוריית "ביטול" של הפרויקט כולו, עם אפשרות ליצור ענפים (גרסאות מקבילות) ולעבוד יחד עם אחרים.

‏Git הוא הכלי הסטנדרטי לכך, וכמעט כל פרויקט תוכנה משתמש בו. **GitHub** ו-**GitLab** הם אתרים פופולריים שמארחים פרויקטי Git ברשת, כך שאפשר להגיע אליהם מכל מקום.

### מושגי יסוד

- **מאגר** (repository, ובקיצור repo): תיקיית פרויקט ש-Git עוקב אחריה
- ‏**Commit:** תמונת מצב שמורה של השינויים, עם הודעה שמתארת מה עשיתם
- **ענף** (branch): גרסה מקבילה של הפרויקט, למשל כדי לנסות תכונה חדשה בלי לגעת בגרסה הראשית
- ‏**Remote:** עותק של המאגר בשרת (כמו GitHub)
- ‏**Pull ו-Push:** הורדת שינויים מה-remote והעלאת שינויים אליו

### פקודות שימושיות

| פעולה | פקודה |
|---|---|
| התחלת מעקב אחרי תיקייה | `git init` |
| מה השתנה | `git status` |
| השינויים עצמם | `git diff` |
| הכנת קבצים ל-commit | `git add file.txt` (או `git add .` לכולם) |
| שמירת תמונת מצב | `git commit -m "describe what you did"` |
| היסטוריית ה-commits | `git log --oneline` |
| הורדת פרויקט מ-GitHub | `git clone https://github.com/user/repo.git` |
| קבלת השינויים האחרונים מה-remote | `git pull` |
| העלאת השינויים | `git push` |

### הצגת העבודה בפומבי עם README.md

‏GitLab ו-GitHub מציגים אוטומטית כל קובץ בשם `README.md` כדף מעוצב למי שנכנס לפרויקט. כותבים מסמך Markdown, מעלים אותו (push), והוא מיד גלוי מכל מחשב או טלפון: מעין אתר קטן, בלי שום הקמה נוספת.

### שימוש ב-Git מתוך VS Code

אין צורך לזכור פקודות. ל-VS Code יש ממשק Git מובנה שמקל מאוד על העבודה:

1. לחצו על סמל **Source Control** בסרגל השמאלי (או `Ctrl+Shift+G`)
2. תראו רשימה של כל הקבצים ששיניתם
3. לחצו **+** ליד קובץ כדי להכין אותו לשמירה (stage)
4. הקלידו הודעה קצרה שמתארת מה שיניתם
5. לחצו על **סימן הוי** כדי לבצע commit (לשמור את תמונת המצב)
6. לחצו **...** ואז **Push** כדי להעלות את השינויים

זו דרך קלה מאוד לנהל ולגבות את הקבצים.

### טיפים

- קלוד יכול לטפל ב-Git בשבילכם: פשוט אמרו "עשה commit לשינויים שלי"
- אין צורך לשנן פקודות: קלוד או הממשק של VS Code יעשו את זה בשבילכם
- אם משהו משתבש ב-Git, בקשו מקלוד עזרה בתיקון

> **לקריאה נוספת:** [Git Handbook (GitHub)](https://guides.github.com/introduction/git-handbook/)

## קלוד למתקדמים

### ‏Skills (פקודות סלאש)

‏Skills הם קיצורי דרך שאפשר להקליד בצ'אט של קלוד ב-VS Code. הקלידו `/` כדי לראות את הרשימה המלאה. הנה כמה שימושיים:

| פקודה | מה היא עושה |
|---|---|
| `/help` | מציגה עזרה ואת הפקודות הזמינות |
| `/plan` | עוברת למצב תוכנית לפני שינוי גדול |
| `/code-review` | בודקת את השינויים שלכם ומחפשת באגים |
| `/simplify` | בודקת את הקוד ששיניתם ומבצעת ניקיונות ושיפורים |

אפשר גם ליצור **skills מותאמים אישית**: קובצי Markdown (`.md`) עם הוראות לקלוד. למשל, skill שמסביר לקלוד איך לעצב מסמכים בסגנון של הצוות, או איך להכין דוח מסוג מסוים. Skills כאלה נשמרים בתיקיית הפרויקט ואפשר לשתף אותם עם הצוות.

### הרשאות: עוד פרטים

כמו שראינו במדריך הבסיס, קלוד מבקש רשות לפני שהוא מבצע פעולות. הנה הסבר מעמיק יותר:

**סוגי הרשאות:**

| סוג פעולה | דוגמאות |
|---|---|
| **קריאת קבצים** | פתיחה וקריאה של קבצים בפרויקט. בדרך כלל מותר אוטומטית |
| **עריכת קבצים** | שינוי, יצירה או מחיקה של קבצים |
| **הרצת פקודות** | הרצת פקודות טרמינל כמו `python script.py`, `pip install`, `git push` |

**כשקלוד שואל, אלה האפשרויות:**

- ‏**Yes:** מאשר את הפעולה הזו בלבד
- ‏**Yes, don't ask again:** מאשר את סוג הפעולה הזה בתיקיית הפרויקט הנוכחית. קלוד זוכר את זה ולא ישאל שוב על פעולות דומות בפרויקט הזה, אבל ימשיך לשאול בפרויקטים אחרים.
- ‏**No:** דוחה את הפעולה

**הגישה המומלצת:**

- **מתחילים:** אשרו כל פעולה בנפרד. כך תראו בדיוק מה קלוד עושה ותלמדו מה קורה.
- **כשמרגישים בנוח:** השתמשו ב-"Yes, don't ask again" לפעולות שאתם סומכים עליהן, כמו עריכת קבצים בפרויקט. זה מאיץ את העבודה.
- **היזהרו עם:** פקודות שמתקינות תוכנות (`pip install`), מוחקות קבצים (`rm`) או מעלות קבצים לאינטרנט (`git push`). כדאי לבדוק אותן גם כשיש לכם ניסיון.

‏**CLAUDE.md לכללי הפרויקט:**

כמו שהוזכר במדריך הבסיס, אפשר ליצור בפרויקט קובץ `CLAUDE.md` עם הוראות קבועות לקלוד. זה שימושי גם להרשאות: למשל, אפשר לבקש מקלוד לשאול תמיד לפני מחיקת קבצים, או לא להריץ פקודות מסוימות.
